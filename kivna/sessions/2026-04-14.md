## Gotchas
- `"source": "local"` does not exist in the Claude Code plugin schema. Valid types: `"github"` (with `repo`), `"git"` (with `url`), `"url"` (with `url`). A single invalid field in settings.json causes the ENTIRE file to be skipped, not just the invalid entry. This means one bad marketplace entry can silently disable all plugins, hooks, and permissions.
- Hook paths in settings.local.json hardcode the cached plugin version number. Every `claude plugins install kerd` update leaves stale paths behind in every repo. No dynamic resolution available in the current plugin system.
- Plugin `marketplace.json` uses `"source": "url"` for self-referencing (not `"local"`, not `"github"`). The `extraKnownMarketplaces` in settings.json uses `"source": "github"` for GitHub repos. Different schema, different valid values.

## Insights
- The settings.json validation is all-or-nothing. One typo in an optional field and you lose everything. This is a footgun — there's no partial loading or warning-and-continue. Worth raising as feedback to the Claude Code team.
- Hook version pinning is a recurring maintenance burden. Every Kerd update requires touching settings.local.json in every repo. This should be a tend check.

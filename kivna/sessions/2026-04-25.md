## Insights

- **Subsume vs. compose** is a useful framing for evaluating new skills. When a skill is adjacent to a plugin's identity, the question isn't "is it useful?" — almost any skill is — it's "do we own this, or do we recognize it?" Kerd already has composition patterns (lorg recommends external skills, mode orchestrates them); council fit that pattern naturally without ownership. Worth applying to future skill-bundling questions.
- **Preamble + fill-in is itself a generative pull.** Anti-hallucination rules can fight the pull, but removing the pull entirely (bare headers + rules in surrounding prose) is structurally stronger. The same rules with brackets present would still leak some padding because the bracketed prompt is the autocomplete cue. Generalizes: structural fixes beat rule-based fixes when the structure is what triggers the bad behavior.
- **Cached-plugin vs. source-of-truth tension.** Executed this switch-out using the cached 0.32.0 skill file (with old fill-in template) but applied the v0.34.0 rules authored today. This is real friction in the plugin distribution model: the rules I just shipped won't take effect for the user (or for me on this machine) until `claude plugins install kerd` runs. Worth thinking about whether tend should flag stale cached versions on switch-in, alongside the existing hook-version concern.

## Insights

- **The recursive trap is genuinely deep.** I shipped 5 sets of text-in-markdown rules as the response to a diagnosis that text-in-markdown rules are the wrong granularity. The sensei review caught it. I named it and chose Path A reframe — which is *itself* text-in-markdown at turn-start. The reframe makes the trap visible to the reader but does not escape it. **Honest framing is not the same as structural fix.** Path B is the only available structural escape from inside Claude Code's hook architecture, and even Path B (Stop/PostToolUse hooks) operates post-response, not at claim-formation. Substrate limit.
- **Convergence is evidence of agreement on shape, not correctness of the shape.** Both spike retro and sensei A3 converged on more-text-rules. Convergence felt at the time like validation. The sensei review demonstrated it was instead two methodologies sharing the same blind spot. Generalizes: when two analyses agree, treat that as a confidence signal worth empirically testing, not as evidence to ship without testing. Adopted as a revised principle in vault Skill Lessons.
- **User-pushback rate is the load-bearing measurement signal for calibration interventions.** Per sensei review's load-bearing observation: self-audit by the same agent that committed the failures inherits the root-cause problem. The only externally-anchored signal in the calibration measurement table is user-pushback rate. All self-audit metrics should be demoted to leading indicators. Adopted in vault Skill Lessons; should inform how Path B (if shipped) is measured.
- **The honest-framing-vs-structural-fix distinction has implications beyond this trap.** Many discipline rules in Kerd skill files are honest framings dressed as structural fixes. The v0.34.0-v0.38.0 work shows what the limit looks like: text rules read at turn-start can become more specific (downgrade vocabulary, citation tags, evidence pointers) but cannot move the granularity of when discipline fires. The genuinely structural mechanisms in Kerd are mode markers, hooks, required artifacts (commit graduation), and approval gates. Future skill design should distinguish more clearly between "more specific text rule" (genuine improvement at the existing granularity) and "structural fix" (changes when/how the rule fires).

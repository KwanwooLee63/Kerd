## Key Decisions

- **LLM Council stays out of Kerd.** Identity dilution argument: Kerd's surface is workflow discipline; council is a thinking tool. Composition argument: Kerd can recognize council artifacts (mode strategy could list it as a step, kivna save could detect council transcripts and propose vault filing) without owning the skill. Reasoning recorded in conversation, not memory — council is unlikely to come back as a Kerd question.
- **Switch+kivna template fix kept narrow.** Dian/tend playbook scaffolds use the same fill-in pattern but were left alone because playbook is intentionally code-shaped (Stack/Setup/Structure of a software project). Out of scope unless we redesign playbook for non-code work.
- **Mode name `spike` over `rapid`.** User's framing — "based on the bigger idea but throw things at the wall" — clarified the mode is *directional but exploratory*, not aimless. "Spike" carries that nuance better than "rapid."
- **Spike mode: wins AND losses both first-class.** User-driven addition during design. Most discipline frameworks track positive progress only; spike work generates as much value from disproven assumptions as from confirmed ones, so both get evidence-cited entries in the captured-evidence file.
- **Commit graduation as an explicit step.** Also user-driven. Ensures spike work survives as extractable solutions for the real build, rather than getting buried in WIP commits indistinguishable from disproven attempts.

## Insights

- **Subsume vs. compose** is a useful framing for evaluating new skills. When a skill is adjacent to a plugin's identity, the question isn't "is it useful?" — almost any skill is — it's "do we own this, or do we recognize it?" Kerd already has composition patterns (lorg recommends external skills, mode orchestrates them); council fit that pattern naturally without ownership. Worth applying to future skill-bundling questions.
- **Preamble + fill-in is itself a generative pull.** Anti-hallucination rules can fight the pull, but removing the pull entirely (bare headers + rules in surrounding prose) is structurally stronger. The same rules with brackets present would still leak some padding because the bracketed prompt is the autocomplete cue. Generalizes: structural fixes beat rule-based fixes when the structure is what triggers the bad behavior.
- **Cached-plugin vs. source-of-truth tension.** Executed this switch-out using the cached 0.32.0 skill file (with old fill-in template) but applied the v0.34.0 rules authored today. This is real friction in the plugin distribution model: the rules I just shipped won't take effect for the user (or for me on this machine) until `claude plugins install kerd` runs. Worth thinking about whether tend should flag stale cached versions on switch-in, alongside the existing hook-version concern.

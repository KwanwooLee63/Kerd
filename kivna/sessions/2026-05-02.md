## Key Decisions

- **Interrogate as standalone skill (option A), not mode or dian flag.** The breadth — 12+ domains spanning technical, business, legal, operational — is bigger than dian's engineering shape. Mode infrastructure forces multiple-choice phase prompts at session start, exactly the cop-out pattern the skill rejects. Standalone keeps it clean; can still be invoked from inside dian or any mode.
- **SDD with spec-review-only (option b), not full SDD.** For markdown transcription + JSON edits + README, the spec-compliance review catches transcription drift; code-quality review is mostly a no-op since there's no executable code. Saved roughly 11 subagent invocations without losing the gate that mattered.
- **Direct work on main, not worktree.** SDD's required workflow skill (`using-git-worktrees`) prefers isolation, but Kerd's project convention is direct-to-main with immediate push (every commit in recent history lands on main). User explicitly authorized direct-to-main for this work; convention won.
- **Sign-off ritual: typed `signed` over commit-message signing.** Commit-message signing introduces git-state ambiguity and forces the skill to reason about commits and authors. v1 keeps sign-off in-conversation. Future versions may reconsider.
- **`metadata.description` drift left intentional.** Pre-existing structural difference (marketplace one-liner vs capability list) — homogenizing would lose the marketplace summary. CLAUDE.md release checklist updated to reflect reality rather than overwriting metadata.description.
- **Scope as a boundary concept, not a tracking concept.** What's in *and* what's out together define the project. Both are scope. Deferred is structurally separate (timing, not boundaries). User-driven design refinement that improved document clarity.

## Gotchas

- **TODO.md / vault Status.md staleness as a calibration risk.** I cited yesterday's "cache at 0.32.0" multiple times as if it were current state. The user caught it: cache was 0.38.0 before today's install, not 0.32.0. Lesson: snapshots in TODO.md and vault Status.md are point-in-time records, not live signals. The global CLAUDE.md discipline gate ("verify that the memory is still correct and up-to-date by reading the current state of the files or resources") applies to *project* memory artifacts too, not just LLM-side memory. Add to playbook: when a new session starts, treat TODO Context block facts about *external* state (cache versions, install state, third-party system status) as candidates for verification, not citation.
- **Plugin cache vs. running-session lag.** `claude plugins install kerd` updates the cache file but the running session still loads the previous cached version. The new skill is on disk + cache but not invokable until restart. The skill loaded for `/kerd:switch` in this turn confirms it: path is `kerd-marketplace/kerd/0.38.0/skills/switch`, not 0.39.0. Worth noting for future install workflows.
- **Naive grep over markdown with embedded code blocks.** My implementation plan's verification step `grep -c "^## "` returned 10 instead of 4 because the canonical template embeds literal `## Scope` etc. inside a code fence. The implementer correctly flagged this as a verification-design flaw, not an implementation flaw. Fix-pattern for future plans: when a section embeds markdown examples, write verification that distinguishes code-fence content from real headings (e.g., grep for the exact heading text rather than just `^## `).

## Insights

- **User-pushback rate landed exactly as the sensei review predicted.** Yesterday's review named user-pushback as the only externally-anchored truth signal for calibration interventions; same-agent self-audit inherits the root-cause problem. Today's TODO-staleness pushback is a concrete N=1 data point. Small, costless to surface, and would have stayed silent without the user catching it. Keeping it in the session log so the count of these data points accumulates over sessions.
- **SDD with fresh-context subagents caught a real drift (Task 8) precisely because they had no session memory.** A subagent dispatched without context for "the way it's been" stopped at the metadata.description mismatch and reported it instead of homogenizing silently. This is the structural value of subagent isolation — agents without history don't paper over inconsistencies they don't recognize. Worth keeping in mind when choosing between inline execution and SDD: if the work touches state where pre-existing drift might exist, fresh-context dispatch is the structural antidote.
- **Brainstorming-to-spec produced a tighter design than I'd have written from scratch.** Five rounds of precision feedback (sign-off ritual, session state, status semantics, scope reframe, final-session-state move) substantively improved the spec. The final design is implementation-ready in a way the first draft wasn't. Pattern: when designing skills that depend on agent-shape (not just executable code), expose the design to several refinement rounds before locking. The cost is paid in conversation turns; the savings are paid in implementation-time clarity and post-ship rework.
- **Honest framing about the recursive trap survived this release.** Interrogate ships as text-rules-at-turn-start — the same granularity yesterday's sensei review flagged. The skill's discipline is structurally anchored (user-veto, frontmatter session state, structural doc check) which should grip more than pure rules, but "should" is a hypothesis. The release notes and design doc both name this honestly — the framing didn't slip into "this fixes the calibration problem" during the design or implementation. Path A reframe holding so far. Whether it holds at runtime is the empirical test.

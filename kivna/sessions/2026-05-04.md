## Key Decisions

- **Question-formation discipline promoted from skill-internal to global claim-discipline.** Originally encoded only inside `/kerd:interrogate` (one-question-at-a-time, no-multiple-choice, drilled). Today raised to a gate in `~/.claude/CLAUDE.md` so it applies to every session, not just interrogations. Rationale: the frustration pattern that birthed interrogate happens everywhere; building a 288-line skill to encode the floor everywhere would have meant the discipline was respected inside the skill and abandoned outside it. The skill stays as deep treatment for plan-readiness; the gate becomes the universal floor.
- **Three-layer model adopted explicitly in Claim Discipline.** Previously framed as binary (turn-start vs. mid-claim). The new three-layer framing (turn-start, mid-claim, response-end) gives the file a layer map — each gate locates its failure on the map and intervenes there. Future drift can be diagnosed by asking "at which layer did this fail?" and the answer dictates where the gate goes.
- **Internal-vs-external distinction in Memory-citation gate.** Without it, the rule would force re-verification of every memory-cited fact, which would be paralytically expensive. With it, only volatile external facts (cache versions, install state, third-party-system status, dates of recent events) trigger re-verification; internal-state facts (decisions made, conventions chosen, code structure) decay slower and can usually be cited as-is. The distinction is what makes the gate cheap enough to actually fire — gates that are too expensive to enforce silently fail.

## Gotchas

- **The closing-list anti-pattern is generated by cooperative wording.** "Surface the gap so we can work on it together" reads as good and collaborative; that's exactly how it produces the closing-list pathology. Cooperative wording in calibration rules generates performative cooperation in output. ## Insights

- **Skill-level discipline that should apply globally is structurally fragile.** Interrogate's question-formation discipline lived only in a single skill's flow — meaning agents respected it inside interrogations and abandoned it elsewhere. Same shape as a project-level convention that should be company-wide: local enforcement leaks pressure on contexts where the discipline should grip. The promotion pattern (skill rule → claim-discipline gate) is worth keeping in mind for other skill-encoded disciplines that show up as user-pushback in non-skill sessions. Diagnostic question for future skills: "does this discipline only apply inside this skill, or is it a universal floor that just happens to need extra structure inside this skill?" If universal, promote to gate.
- **Cooperative-but-performative wording is a hidden category of bad rules.** "Surface the gap so we can work on it together" sounds healthy and gets the principle right, but generates the wrong output shape. The trap: the rule's intent is fine; its wording invites the performative version of that intent. The fix is always to make the rule directive about the action shape, not collaborative about the principle. Captured as a lesson in `Kerd Skill Lessons.md`.
- **Two parallel experiments now running on whether text-rules-at-claim-formation can grip.** Interrogate's structural anchors (frontmatter session state, user-veto on stop) experiment at the skill layer. The eight gates in claim-discipline experiment at the global layer. Both are text-shaped. If both grip, text rules at the right granularity work and Path B stays paused. If both fail in the same shape (closing lists keep appearing, sliding sideways keeps happening), text rules anywhere are insufficient and Path B (Stop hooks scanning for structural patterns) becomes the next escalation regardless of layer. The empirical signal — user-pushback rate — is the cross-layer truth signal; today's interrogate test produced two on turn 1, an early data point.
